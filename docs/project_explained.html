StriSakhi - Project Explained

StriSakhi ("woman's friend") is a prototype that gives women simple Hindi legal information from three Indian law PDFs. It runs on one laptop and is used from an iPhone browser on home Wi-Fi. It gives information, not legal advice.

1. The big picture

A woman types or speaks a question in Hindi. The laptop finds the most relevant paragraphs in the law PDFs, gives only those paragraphs to a small AI model, and the model writes a short Hindi answer that names the law and section. A fixed safety footer is always added.

2. Architecture (how a question travels)

iPhone Safari - one web page: text box, ask button, mic button, answer, source, footer.
↓ Wi-Fi (https, because the iPhone mic needs it)
FastAPI server (Python, on the laptop) - receives the question or audio.
↓ (voice only) ffmpeg converts audio → Gemma transcribes it → user corrects the text
Retriever - turns the question into numbers with bge-m3, asks ChromaDB for the 3 closest chunks of law text.
↓
Gemma 4 E4B via Ollama (localhost only) - reads the chunks + system prompt, writes the answer.
↓
Response = answer + source (law, section, file, page) + fixed footer from a file. The phone can read it aloud.

4. The LLM logic (RAG)

RAG = Retrieval-Augmented Generation. The model does not "remember" the law; we hand it the relevant text each time.

  1. Index once: PDF → text with page numbers → chunks → embeddings → ChromaDB (with file, page, law, section).
  2. Retrieve: embed the question, fetch the top 3 closest chunks.
  3. Prompt: system prompt rules + the 3 chunks + the question.
  4. Generate: Gemma answers in simple, short Hindi, thinking turned off for speed.
  5. Attach: source line and fixed footer, added by our code, never written by the model.
System prompt rules: answer only from the given text; simple Hindi; short; name the law and section from the source; if the answer is not in the text, say "I do not know from the available text"; give information, not advice.

5. Safety and privacy

  • Footer is fixed text in a file (112, 181, 15100 - TO VERIFY on official sites).
  • Never invent laws, sections, numbers or helplines.
  • Old IPC/CrPC sections are flagged; since 1 July 2024 BNS, BNSS and BSA replace them.
  • No names, phone numbers or audio are stored. Audio is deleted right after transcription.
  • Ollama listens on localhost only; only the FastAPI page is reachable on the Wi-Fi.

6. Memory on a 6 GB GPU

Gemma 4 E4B (about 6.6 GB on disk, quantised) is already close to the limit, so part of it may run on the CPU/RAM. bge-m3 is small (1.2 GB) and only runs for a moment per question. Ollama loads and unloads them as needed, so they take turns rather than fight; the cost is a short delay when switching.
